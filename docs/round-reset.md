# 本轮测试重置

## 使用

使用新构建的 brain、game_controller，以及新裁判盒。启动方式与原来相同；game_controller 增加 `enable_test_reset` 参数，默认 true，可在 launch 中用 `enable_test_reset:=false` 禁用扩展。

桌面版连接设置增加“重置第一队球员编号”，默认1。网页启动参数为 `--reset-player`。点击“重置本轮”会保持 INITIAL 并发送一个新请求；已经处于 INITIAL 时同样可以重置。请求待确认或超时期间禁止进入 READY/PLAYING，超时后重试沿用原ID。完成提示确认的是 brain 的内部清理和停止请求发布，不是底层停车应答。

普通 INITIAL 状态从其他状态切入时也会自动重置一次；每0.5秒收到的重复 INITIAL 包不会反复重置。

重新定位期间保持 INITIAL。vision 使用现有边线入场定位先验，需将机器人摆在支持的入场区域；simulation_ground_truth 等待重置之后接收的新有效位姿。READY/PLAYING 在新定位建立前不允许行走。收到新真值后可正常继续；vision 如果过早切出INITIAL，则应返回INITIAL进行入场定位。

此功能不复位仿真机器人、球或时钟。需要重复物理起点时，先确认停稳、在仿真界面摆回机器人和球，再重置本轮。

## 实现

- UDP原端口增加文本扩展：`RBR1 <32位十六进制ID> <team> <player>`；回复 `RBA1 <ID> <team> <player> complete|busy|agent_mode`。普通裁判数据包格式不变。
- game_controller 校验长度/ID/队号/球员范围及既有IP白名单，维护有界、过期的回复地址表，通过ROS String话题转发请求与反馈。
- brain 只接受匹配自身队号和球员号的请求，agent模式拒绝。回调只设置待执行状态；实际清理在tick线程持锁执行，清理结束后回复。最近256个已完成ID保留到进程结束，重试去重不跨进程持久化。
- 重建行为树和黑板，保留裁判开球方/判罚；转入INITIAL，清理球、地标、障碍、视觉区域、协作决策、开球等待、定位变换与动作计时，运动客户端避障缓存改为可重置成员。
- 保留静态配置及真实传感器状态，不将真实里程计伪造为零。旧时间戳的检测/线段/深度帧被忽略；无时间戳的Pose2D真值只保证重置后接收，不能证明其采样时间。
- 中断行走动作时发零速；重置显式请求停止VisualKick、切回WALK及零速度。INITIAL及本轮未定位期间，在速度出口再次强制零速。
- ROS回调、行为树tick和队友策略状态访问使用同一递归锁，避免重建树与节点执行/队友访问并发。

## 验证与边界

使用独立Docker容器（network none）、ROS_DOMAIN_ID=97、ROS_LOCALHOST_ONLY=1和专用测试机器人话题进行隔离验证。测试涵盖三轮状态序列、普通INITIAL边沿、INITIAL内再次重置、请求去重、错误球员过滤、反馈、旧球检测过滤、普通Kick/VisualKick退出、vision未定位门控、真值重新获取，以及原有真值定位回归。

底层运动控制器没有参与测试；未验证实际停车响应、真实定位收敛或实场踢球。重置和状态UDP均无认证，适用于受信任调试网络。一个请求只针对指定brain；同一裁判盒仍对两队广播普通比赛状态，不能把单机完成回执理解为整队完成。
